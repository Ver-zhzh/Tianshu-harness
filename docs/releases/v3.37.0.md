# v3.37.0 — 提交/验证/审查契约分离与默认工具面收口

> 日期：2026-10-26
> 上一版本：v3.36.1

## 本版说明

本版是一次**行为契约**发布，主线有两条：

一是**提交、验证、审查彻底分离**。此前 `deliver_task` 把提交、验证、审查混在一个调用里：默认 strict 验证链、提交后自动派审查、回执附带质量背书。本版起 `deliver_task` 收敛为纯安全提交（归属校验 + Git 保护 + 限定范围提交），验证走 `run_tests`、审查走新增的 `review_changes`，两者都由调用方显式发起，不再有任何自动触发。回执只披露事实，不再替质量背书。

二是**默认工具面收口**。十五星域共用的默认主控面从 30 件精简到 26 件，`galaxy` / `starflow` / `plan_task` / `council_convene` 移出默认面改为按需挂载，工具定义体积下降 23.2%；高级编排入口收进新增的 `orchestration` 档。默认 `/team` 直接消费 Markdown 计划，不再需要 `plan_task`。

两条主线指向同一个原则：默认形态做减法，升级路径显式化。此外桌面端自动更新做了断点续传与来源校验，默认主题切换为纯白圣殿（aether-citadel），并收编了四个社区 PR。

## 内容清单

- **契约分离（主打，含行为变更）**：
  - `deliver_task` 收敛为纯安全提交：删除 verification_policy / review_level / review_policy / skipAutoReview / review_findings / checklist / learned 七个混合参数（携带即无副作用退回并指向独立入口）；strict 候选物化、影响分析、quorum 门禁、RED/YELLOW 硬拦、提交后自动审查路由整段拆除；全部 Git 安全保护（归属、半暂存、index 锁、敏感路径、跨会话 claim 冲突、cohesion 门禁、真实 SHA 回执）保留。
  - 新增 `review_changes` 独立审查入口（start / list / update）：固定审查快照基准（显式 files/commit_ref/range > 已归属 dirty > 最近提交），默认单只读 reviewer，只读——不测试、不修码、不提交；发现持久化到 review-inbox，期间代码变化不自动重审；`applied`（未提交补丁）与 `fixed` 分开，不冒充已提交修复；`/review` 在 TUI 与桌面端同源于此入口。
  - `run_tests` 空参数不再默认全量：返回范围预览与全量启动指引；项目在 `.rivet-config.json` 的 `verify.test` 显式声明的默认命令除外。
  - `galaxy` / `starflow` 的 `autoReview` 默认 true→false（显式传 true 仍可用）；`agent.review.skipAuto*` 配置标注废弃但读取兼容；桌面端「自动审查」开关保留读写兼容，回执注明提交不再触发自动审查。
  - 审查质量链修复：发现的 severity 逐条读取（不再共享摘要）、结果按会话分区、未解决发现持久化、verified 结论下保留 LOW 级缺陷；审查 worker 强制只读并基于不可变快照。
  - `deliver_task` 回执新增被动风险提示（package.json / migration / security / config 四类风险面，至多 3 项，纯文档改动不提示）。
  - issue #537 修复链：提交失败按原因归因（HEAD 变化 / index 变化 / 文件内容变化 / 基准缺失分开报）；CRLF 工作区不再让候选快照误判「不可用」（ref 哈希行尾归一化）；scoped commit 不再被 stale 路径误报；零验证记录时不再断言「Typecheck passed」。
  - `deliver_task` 性能：只读检查跳过 advisory 的外部命令核验；台账一次执行只读两次、有效验证按参数复用；提交前 HEAD 复用省掉一次 rev-parse；advisory 检查失败必须可见，不再静默吞掉。

- **默认工具面收口与 orchestration 档**：
  - 默认 minimal 主控可见 30→26 件，装配 36 件；工具定义从 44,640 字符降到 34,285（-23.2%），前缀更轻。
  - `galaxy` / `starflow` / `plan_task` / `council_convene` 在非太一档冷注册，显式 `/galaxy`、`/starflow`、`/council` 按需挂载；`git_scout` 移出默认主控面（主控用 `git`，只读 worker 的 Git 查询能力不变）。
  - 新增 `orchestration` 档：仅在 minimal 之上默认开放四个高级编排入口，不含浏览器、安装器等重型集合；frontend = minimal + browser_debug；full 保持原能力并开放 council_convene；太一评测档不变。
  - `/tools` 与桌面设置显示实际装配数与主控可见数（visible / cold / unregistered / disabled 等状态分列）；桌面经只读 `GET /sessions/:id/tools` 查询，不编造计数。
  - 运行时三处遗漏修复：首请求后显式启用工具不再被冻结的工具表吞掉（授权一次新缓存代次）；无头 `-p` 入口与交互装配对齐（此前 minimal 实际只有 20 件）；模型替换不再丢显式启用项、不把档位升级为 full。
  - 配置入口：`tools.preset=orchestration`、`RIVET_TOOL_PRESET`、TUI 配置面板、桌面设置；优先级不变，已有会话冻结当前装配不自动升级。详见 `docs/reference/tool-surface-presets.md`。

## 升级注意

本版行为变更集中，升级前请过目：

- `deliver_task` 提交时**不再自动跑验证、不再自动派审查**，回执也不再作质量背书。需要验证就显式 `run_tests`，需要审查就显式 `/review` 或 `review_changes`。
- `run_tests` 不带参数不再跑全量，只给范围预览与启动指引（项目显式声明的默认命令除外）。
- 默认工具面从 30 件缩到 26 件：`galaxy` / `starflow` / `plan_task` / `council_convene` 需显式挂载（`/galaxy` 等斜杠命令照常），或整体切到 `orchestration` 档。工具目录变化会带来一次前缀缓存冷启动。
- 自动记忆形成默认关闭，可在桌面「设置 → 行为」或配置 `agent.memoryFormation.autoCapture` 重新打开；既有记忆正常召回。
- 桌面端默认主题变为纯白圣殿（aether-citadel），可在「设置 → 个性化」改回。
- Node 运行时要求与 v3.36.0 起相同：24.x ≥ 24.22.1 或 26.x ≥ 26.12.1，低于安全线拒绝启动。

## 已知限制

- **3.36.x 桌面客户端的应用内升级链有缺陷，可能收不到/装不上本版**（发版实测）：3.36.0 重启落装时「安装清单恢复失败」卡死；3.36.1 经 AtomGit 源下载 stall 在 0MB（源本身满速，系老客户端实现问题）、且「会话数据落盘核对」在 0 失败 0 待保存时误拦（「仍然更新」同样被拦）。**3.36.x 用户请手动下载 DMG/setup 覆盖安装一次**（数据在本地不受影响）；本版重做的更新器（断点续传/来源校验/损坏自恢复）从 3.37.0 起接管后续更新。落盘核对误拦的根因遮蔽（前端统一报错丢真实错误码）与残余抛出点未纳入「仍然更新」覆盖，拟 3.37.1 修。
- `review_changes` 的发现以固定快照为基准持久化，期间代码变化不触发自动重审，需要显式再次发起。
- `RIVET_READONLY_ADVICE_EXPERIMENT`（只读建议跳过实验）保持默认关闭，shadow 仅观测；真实模型行为收益尚未测量。
- 桌面端「自动审查」开关为兼容保留项，拨动不再改变提交路径行为。
- 恢复观察配对实验已完成两轮真实模型重放（36 trial），单场景结论互有胜负，默认策略未因此调整。
