# 手机端操作手册

> 在手机/平板上连接天枢桌面端：扫码或令牌接入，远程查看会话、处理审批、发起新任务。
> **同一 Wi-Fi 直连（2026-10-08 起，Issue #402）**是推荐路径——桌面端开关 + 手机扫码 ≤2 步、免装 Tailscale；手机不在同一网络时走 HTTPS 隧道。
> 本手册面向使用者；机制细节与安全边界的设计说明见 [远程访问指南](../remote-access.md)，直连设计依据见 [Issue #402 响应设计](../design/2026-10-08-issue402-lan-direct-connect.md)，往 `/mobile` 添加自定义页面见 [自带 /mobile 页面](../mobile-custom-page.md)。

## 它是怎么连的

桌面端运行时会同时托管两样东西（同一端口、同一进程）：

- **`/mobile` 页面** —— 手机端界面。静态资产，打开**无需令牌**（这样手机浏览器才能先拿到页面本身）；
- **运行时 API** —— 会话 / 审批 / 任务接口。**令牌门控**，无令牌一律拒绝。

手机浏览器打开 `/mobile` 后，页面与你桌面端**同源直连**（无 CORS、无云端中继、无账号体系）——访问令牌是唯一凭证，数据始终在你的局域网（或你自己的加密隧道）内流动。

## 前提

- **同一 Wi-Fi 直连（推荐）**：手机/平板与电脑连在同一个 Wi-Fi，无需任何额外软件；
- **不在同一网络**：手机与电脑能通过 Tailscale 或你自己的 HTTPS 隧道互通（见下文「不在同一网络：HTTPS 隧道（Tailscale）」章节）；
- 桌面端安装版**自带手机页面**（随安装包分发，开箱即用）；老版本建议先升级。

## 第一步：同一 Wi-Fi 直连（推荐）

手机和电脑连同一个 Wi-Fi，全程 ≤2 步，不装任何软件、不注册账号：

1. 桌面端 **设置 → 网络 → 远程访问**，打开「**同一 Wi-Fi 直连**」开关（默认关）。首次开启时若系统弹出**防火墙提示，请选择允许**——否则手机会连不上。
2. 点令牌旁的「**显示**」，用手机相机（或微信）扫下方二维码 → 自动打开连接页并**自动连接**。令牌随即从手机地址栏被清掉，只保存在手机本地。

开关打开后，设置页会显示手机入口链接 `http://<电脑局域网 IP>:<端口>/mobile/#token=…` 与安全告知。也可不用扫码，直接在手机浏览器打开该链接，或在配置页粘贴**访问令牌**（服务器地址自动填为页面来源地址）。

> 端口以设置页「访问地址」显示为准——桌面端使用动态端口，每次启动可能不同；二维码与地址列表始终反映当前实际端口。换到一个新的 Wi-Fi 后电脑的局域网 IP 会变，旧链接失效，重新扫码即可。

用完把开关**关闭**即回到仅本机监听：已连手机断开、端口不可达。开关状态在桌面端持久化，默认关。

> **安全设计**：**令牌处于遮显状态时二维码不会绘制**，避免随手截图泄露令牌。同一 Wi-Fi 直连使用局域网明文 HTTP——知道 Wi-Fi 口令、又能抓到握手的同网者原理上可旁读令牌，故仅建议在**受信任网络**使用、用完即关（细节见下文「安全须知」）。

## 第二步：安装到主屏幕（像 App 一样使用）

手机端没有安装包、也不进应用商店——它是 PWA（渐进式网页应用），「安装」= 浏览器添加到主屏幕：

- **iPhone / iPad（Safari）**：打开已连接的 `/mobile` 页面 → 分享按钮 → 「**添加到主屏幕**」→ 确认。主屏幕上出现天枢图标，点开是全屏外壳（无浏览器地址栏）；
- **Android（Chrome / Edge）**：打开页面 → 右上角菜单 → 「**安装应用**」/「**添加到主屏幕**」。部分机型扫码连接后浏览器会直接弹出安装横幅。

添加一次即可：主屏幕图标保存的是手机本地的连接信息（地址 + 令牌），以后从图标进入**不再需要扫码**——令牌在桌面端重启轮换时才需要重扫一次（见「常见问题」）。

已知边界：桌面端内置的 `/mobile` 页面已带 PWA manifest 与图标（2026-09-26 起），支持上述类原生外壳。**能力随连接方式不同**：

- **同一 Wi-Fi 直连（明文 HTTP）**：`http://<局域网 IP>` 不是安全上下文——**Service Worker / 离线缓存不可用**，浏览器也不会弹出「安装应用」横幅；但**「添加到主屏幕」这类原生外壳在 Android Chrome / iOS Safari 仍可用**。手机必须始终能连到桌面端才能使用。
- **HTTPS 隧道**：安全上下文，具备完整 PWA 能力（含安装横幅）；**离线缓存（Service Worker）同样未支持**——这不是缺陷，而是「页面与数据都不落第三方」这一安全边界的延伸。

## 手机端能做什么

- **会话列表** —— 状态实时推送（连接异常时自动轮询兜底）；有**待审批 / 失败 / 中断**的会话带醒目色条并置顶；支持按正文关键词搜索；
- **会话详情** —— 只读时间线（实时流式）+ **审批处理**（授权 批准/驳回、执行计划 批准/驳回、提问的文本回复）+ **中止运行**按钮；
- **发起新任务** —— 从手机直接新建会话：选项目、输入任务；
- **会话产物** —— 查看该会话的产出。

已知边界（有意设计）：**已有会话不支持发消息/steer 干预**（避免手机上误改长任务的走向）；历史消息不支持「加载更早」冷分页；不支持离线使用（无 Service Worker 缓存，手机需始终能连到桌面端）。刷新页面会回到列表页——扫码直达每次都是干净入口。

## 不在同一网络：HTTPS 隧道（Tailscale）

手机不在同一 Wi-Fi（例如用移动网络）时，改用 HTTPS 隧道：桌面端保持显式监听本机回环（`127.0.0.1`），手机通过 Tailscale Serve 隧道连接。桌面 sidecar 会覆盖继承的 `RIVET_SERVE_HOST`，无需改变这个变量或以管理员身份运行天枢。

1. 电脑和手机安装 Tailscale，登录同一账号；
2. 打开桌面端 **设置 → 网络 → 远程访问**，复制其中的 `tailscale serve --bg --https=443 ...` 命令，在电脑上运行；命令指向当前桌面实例的动态端口；
3. 把 Tailscale 返回的 HTTPS 地址填入设置页的「手机访问地址」，保存；
4. 回到设置页点令牌旁的「**显示**」并扫码 → 自动打开连接页并**自动连接**（与直连同样的扫码/令牌流程，只是地址是隧道 HTTPS 地址）；手动方式：手机浏览器打开 `https://<隧道地址>/mobile/`，在配置页粘贴**访问令牌**（服务器地址自动填为页面来源地址）。

> 已保存 HTTPS 隧道地址时，手机会**优先使用隧道地址**；想让直连地址生效，先移除隧道地址。直连开关与隧道互不排斥。

顶部显示「仅本机可访问」是桌面监听的正常状态；HTTPS 隧道负责远程访问。手机与电脑不必在同一 Wi-Fi，但电脑需要保持运行，且 Tailscale 的访问策略需要允许手机连接该电脑。

**不要把端口直接映射到公网。** 天枢没有账号体系、没有云中继，公网暴露后唯一的防线就是那串令牌。SSH 端口转发（`ssh -L <本地端口>:127.0.0.1:<serve端口> 用户@主机`）更适合从电脑访问，手机场景优先 Tailscale。

旧手册曾推荐永久设置 `RIVET_SERVE_HOST=0.0.0.0`。旧安装版在新增 TLS 检查后可能因此无法启动。尚未升级时，可在普通用户 PowerShell 中临时设置 `$env:RIVET_SERVE_HOST = '127.0.0.1'` 再从该窗口启动天枢；也可用 `[Environment]::SetEnvironmentVariable('RIVET_SERVE_HOST', $null, 'User')` 删除这个用户变量，再重新登录 Windows。新修复版桌面启动不再受遗留值影响；单独运行的 CLI 仍使用自己的监听配置。

## 安全须知

- **令牌 = 完整控制权**，等同密码：不要截图、不要转发、不要写进公开配置；
- **同一 Wi-Fi 直连使用局域网明文 HTTP**：知道 Wi-Fi 口令、又能抓到握手的同网者原理上可旁读令牌——这是「零安装 + 数据不出局域网」的代价，故仅建议在**受信任网络**使用，用完即关（开关默认关）。不接受该残余风险就不要开启。
- **不在同一网络走 HTTPS 隧道**；桌面本机 HTTP 默认只在回环地址监听。独立 CLI 的非回环监听必须配置 TLS（或显式 `RIVET_SERVE_LAN_DIRECT=1` opt-in 明文）。
- **Host 白名单在直连模式下收紧**：默认只放行本机私网地址，公网地址被剔除，未知 Host 一律 403（挡 DNS rebinding）；显式 `RIVET_SERVE_HOSTS_ALLOW` 优先于该默认过滤。
- **首次监听非回环时系统可能弹出防火墙入站询问，请选择允许**；天枢不自动改防火墙规则。
- **令牌与桌面端进程同生命周期**：重启天枢后旧令牌立即失效，手机端会连不上（401）——重新扫码即可；
- 可选收紧：`RIVET_SERVE_HOSTS_ALLOW=192.168.1.5,my-pc.local`（逗号分隔、不带端口）可启用主机白名单，非白名单 Host 直接拒绝。

## 常见问题

| 现象 | 处理 |
|---|---|
| 扫码打开是 **404** | 该服务实例未提供 `/mobile`。桌面安装版随包提供（正常不会出现）；自己用 CLI `rivet serve` 时需要 `RIVET_MOBILE_DIR`（或 `--mobile-dir`）指向含 `mobile.html` 的目录 |
| 打开后**连不上 / 401** | 桌面端重启过，令牌已轮换——重新扫码；或在手机端「更换连接」粘贴新令牌 |
| 同一 Wi-Fi 下手机打不开 | 确认「同一 Wi-Fi 直连」开关已开、手机连着同一个 Wi-Fi，且首次开启时的防火墙询问选了「允许」；换过 Wi-Fi 后电脑 IP 变化，重新扫码 |
| 直连时接口全 **403** | Host 不在允许列表——若电脑处于公网 IP 场景，公网地址被默认剔除；用 `RIVET_SERVE_HOSTS_ALLOW` 显式放行，或改用 HTTPS 隧道 |
| 直连时浏览器不弹「安装应用」 | 明文 HTTP 不是安全上下文，属预期；仍可用「添加到主屏幕」。要完整 PWA 能力（含安装横幅）请走 HTTPS 隧道 |
| 手机打不开地址（隧道） | 检查 Tailscale 是否互通、HTTPS 隧道是否运行，以及隧道是否指向当前桌面端口 |
| 启动报 `Non-loopback access requires TLS` | 旧版桌面可能继承旧手册设置的监听变量；按「不在同一网络」章节移除遗留用户变量或升级修复版。独立 CLI 需配置 TLS、或显式 `RIVET_SERVE_LAN_DIRECT=1` opt-in 明文、或改为回环监听 |
| 想彻底关闭远程访问 | 关闭「同一 Wi-Fi 直连」开关；如用过隧道，执行 `tailscale serve reset` 停止该电脑的 Serve 配置；并清除设置页保存的手机访问地址。`tailscale serve reset` 会停止此电脑的其他 Serve 配置，执行前确认用途 |

快速自检（在电脑上执行，不需要令牌）：

```bash
curl -o /dev/null -w '%{http_code}\n' http://127.0.0.1:<端口>/mobile/   # 期望 200
```
